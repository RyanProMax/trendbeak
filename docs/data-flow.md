# 读取、快照与增量计算

## 请求红线

页面和接口不运行历史指标全量重建、回填任务、后台轮询或无界重试。没有新建表、KV、队列、权限、凭证、付费资源或调度。情绪仍只保存于既有五字段 `sentiment_daily` 表，真实缺口、独立来源和历史均保留。

- `GET /` 只输出约5KB轻壳、市场名称和有尺寸的加载状态，不抓上游、不访问D1、不生成图表。浏览器分别请求CN和US，某个市场失败不会阻塞另一个。失败后保留原有可用浏览器备份并显示重试，首次请求有8秒上游超时上限，不无限等待。
- `GET /api/markets/:market` 返回一个市场的快照，最多640根真实日线和372日情绪（365日可视范围加7日行情兜底余量，情绪日期独立于价格截止日），用于最近365日的指标预热；没有服务端逐日技术指标、热力日历或冗余历史数据。`bars` 标识紧凑传输，`history`、`days`、`signals` 是兼容空容器。其他客户端应按 `src/lib/expand-snapshot.ts` 在客户端/显式离线流程展开，不应把兼容空容器理解为缺行情。
- `GET /api/markets` 已停用批量读取，返回410与按市场入口，不访问数据。旧调用者需改用两个按市场请求；站内页面已适配。冷批量路径本地曾测到约16ms，因此不把它留作可调用的重入口。
- `GET /api/sentiment/:market` 只读D1，单次最多366自然日/366行，默认365日；更早历史用明确日期窗口分段读取。SQL先过滤市场、来源、起止日期，并有373行硬检测上限，不在Worker全表排序或聚合。
- `GET /api/health` 只检查已有行情快照，冷缓存返回degraded；不为了健康检查抓行情、查情绪或生成指标。
- 搜索最多返回10项，输入最多60字符，取得的搜索数组最多100项；缓存和进行中的请求均有上限。

## 快照与频率

行情新鲜期5分钟、最后成功快照最多7天。内存缓存以市场和标的隔离，最多64项；Cache API仅同机房最佳努力保存。两个生产域名共享行情和情绪边缘键，预览域隔离。新行情键使用 `quote-v2`，旧带情绪/计算结果的行情快照不进入新读取链。

外部输入和边缘快照在进入内存时完整验证、冻结；内存命中只检查身份对应的键与年龄，不再深度扫描历史。快照时间只在取得并验证成功数据时改变，失败和读取不会刷新时间。浏览器保留最多6份且总计2MiB的最后成功行情；旧来源情绪不会覆盖来自D1的当前结果。

同实例同键singleflight，行情/情绪/搜索各最多8个进行中键；行情失败退避60秒，并以同机房边缘标记帮助后续冷实例退避。搜索失败内存退避60秒，情绪D1失败同绑定同键退避60秒。情绪快照业务新鲜期5分钟，物理保留最多7天，D1故障可返回原成功时间的同源历史，不将失败伪装成新观测。没有分布式原子锁，不声称跨机房全局去重或零并发回源。Cache API被驱逐时仍允许一次有界读取，绝不触发服务端历史计算。

页面可见时最多5分钟刷新一次，visibilitychange遵守同一间隔；隐藏页面不抓取，切换股票、明确重试等用户动作仍可按需请求。首次加载每市场一次；暂时失败的旧初始数据可保留一次有界恢复，不形成循环。健康检查不消耗回源预算。

行情外部响应限制512KB（含无Content-Length流式响应），日线最多640根。超限、身份不匹配、坏JSON和价格校验失败不进行快速重试。上游超时8秒；腾讯快速暂时网络/5xx错误可等待500ms再试一次；访问拒绝、限流、Retry-After、完整超时不重试。Yahoo对可回退错误最多两个既有域名，拒绝/限流/完整超时停止。

## 指标与修订

`history-engine.ts` 仅供浏览器或显式离线处理。每个标的最多640根日线，浏览器最多保留6个计算状态。初次展开是有界顺序计算，服务器HTTP链路不调用它。

- Wilder RSI14与EMA20/60保存每行递推状态；20日均值、布林和成交量只取必要窗口；每个52周区间只计算一次并复用于历史读数。
- 经验中位秩只使用此前最多252个有效观测，至少60个才绘图；缺失值不占有效观测队列，当前值不进入自己的分位。扫描上限固定252，不再复制和过滤全部前缀。
- 同样日线不重算指标；新日只追加一行。此前盘中末行先结算，最多多处理一行。
- 修订/插入/删除从最早变化日重算后缀，保留此前结果；RSI/EMA具有递归影响，不能只修正当天。复权变化或来源窗口起点变化使最早受影响位置归零，完整重建仅发生于浏览器/离线，不在接口中执行。
- A股优先腾讯qfqday，美股沿用Yahoo quote.close；不混adjclose、其他标的成交量或实验情绪。无未来数据、缺量留空，盘中量能取最近完整交易日。历史可能受到上游复权修订影响，不称为本站当日归档。

## 情绪同步与缺口

同步命令与读取完全分离。日常sync默认今天及此前14日，只upsert明确窗口；更早修订显式 `--from/--to` 且每次最多366日。首次seed是独立受控命令，重复仅补缺。没有配置自动任务，不将部署说成每日同步已启动。

数据来源、覆盖和公开使用边界见 [sentiment-storage.md](sentiment-storage.md)。CN2026-07-27仍是真实缺失；US2026-03-12的21.2只作为CNN／Benzinga同期报道独立读数，不插入社区曲线，不插值、不使用实验自算。日期展示继续本地化，确证休市才统一显示休市。

## 旧客户端迁移与仍待决定的边界

已核对4c00c98实际客户端：它只请求按市场接口，从未请求批量 `/api/markets`。410不是它的兼容问题；它的旧校验器不能接收紧凑bars。按市场请求现在明确要求 `X-Trendbeak-Data: bars-v1`，缺失/不匹配返回426、no-store，发生在行情/情绪读取之前，避免把不兼容数据伪装成200成功或让旧60秒轮询回源。

新页面入口JS/CSS带数据版本查询参数，避开原同URL缓存JS。新Service Worker激活后与根页面握手：支持版本处理的客户端响应版本，不重开（包括已更新得更快的新客户端）；没有响应的旧根页面自动导航一次。激活过程不等待导航完成，避免新文档等待激活而互锁。之后遗留的未带版本API请求也触发同一迁移；不清除localStorage、cookies或日期范围。新客户端还可对未来426版本变化至多自动导航一次。

本机Chrome用精确4c00c98旧JS、旧SW和实际旧HTML验证：更新SW被浏览器发现并成功激活后，旧文档自动重开一次，新版本资源生效，已保存日期范围保留；新客户端不重复重开，旧页面没有批量请求。这个测试主动调用registration.update来模拟“浏览器发现更新”，没有模拟用户刷新，也不证明浏览器会立即检查更新。原选择游标/个股等未持久化状态可能回到默认。

**尚有发布兼容限制**：无SW控制（被禁用、不支持、首次注册失败）的已经运行的旧JS，没有版本/刷新处理器，接口响应不能替换其执行中的JS；已实测426后它会保留旧数据，但不会自动恢复，必须进行一次普通导航。浏览器何时发现SW更新也不由本站保证。不能宣称所有旧标签无缝升级；若必须保证这类旧标签继续完整运行，需要另行明确允许完整V1物化快照的生成、更新和存储，而不能恢复HTTP全历史计算。本轮未增加该存储/调度，也没有部署。

原理边界见 [Service Workers标准](https://www.w3.org/TR/service-workers/#soft-update)。

## 性能测量边界与实际传输

先前6.42/3.60ms是本地Node固定夹具、空应用缓存下的顺序请求，Node宿主Request/Response已初始化，模块导入也在计时外；不是Cloudflare Worker冷启动。新增 `BUDGET_FIRST_PATH=/api/markets/CN npm run test:budget` 可在新Node进程中把首个请求的Web API初始化也计入，进程总CPU另外列出（含夹具与模块导入），仍不能替代Cloudflare。不得声称已通过真实10ms预算。

目前增量是浏览器指标状态、来源特定情绪写入窗口；不是行情上游或HTTP日线的差量协议。冷缓存/全部驱逐/5分钟到期仍按一个市场抓取腾讯最多640条、或Yahoo两年且最多640条真实日线，用完整有界窗口检测修订/复权。HTTP正常返回这些bars及最多372日情绪，不传预计算逐日指标；不传since/cursor、不隐瞒完整有界读取。典型500根测试约59KB，640根测试约71KB/市场，源响应仍有512KB硬上限。

`BUDGET_BURST=1 BUDGET_BARS=640 npm run test:budget` 是4个纯本地夹具请求（CN/US各2个）：同实例只回源2次、D1共3次，重复读取singleflight。全新实例+边缘未命中、不同机房或跨实例同时过期仍可能各自有界回源；当前没有全局分布式锁。并发组CPU是整组CPU，不能拆称每个请求CPU；线上冷启动/跨实例过期峰值尚未验证。
