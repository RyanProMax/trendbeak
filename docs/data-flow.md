# 读取、持久快照与增量更新

## 请求红线

首页、行情、情绪和健康接口不运行回填、历史指标重建、行情源刷新、后台轮询或无界重试。行情与情绪同步是独立命令，尚未配置定时执行。内存和边缘缓存仅减少数据库读取，不能代替持久历史。

- `GET /` 返回约 5 KB、有固定加载尺寸的轻壳：零 D1、零行情上游、零历史计算、零图表渲染。
- `GET /api/markets/:market?symbol=...` 用主键读取 `payload.http.body` 中已生成的完整展示响应：最近 365 日日历、最多 366 个逐日技术读数、有明确来源的情绪及当前元数据。HTTP 不读情绪表，不解析、逐行验证或序列化完整响应；只追加小型新鲜度。预热日线和递推状态不进入 Worker/浏览器，双方都不重新计算技术指标。
- 已存在的完整 V1 展示格式继续可用，不要求版本请求头，不需要强刷或 Service Worker 迁移。`If-None-Match` 未变化返回空体 304；ETag 使用行情快照实际提交时间；情绪修订通过独立准备命令更新该响应和提交时间，读取不会使它变成新观测。
- 未初始化标的返回 404 / `snapshot_missing`，不回源、不回填、不显示假价格。搜索仍返回最多十个真实名称/代码，并以主键查询标记是否已收录；页面显示“历史待收录”，选择失败保留原大盘。必须由操作命令初始化新标的；本次已在既有生产库准备沪深 300、标普 500、NVDA。任意新股票不是即时自动回填。
- `GET /api/markets` 返回 410 和按市场入口，零数据工作。已核对此前实际 4c00c98 客户端不调用此批量接口。
- `GET /api/sentiment/:market` 从唯一的 `sentiment_daily` 五字段表读必要范围。默认 365、最多 366 自然日；更早历史显式分段读取。逐行返回来源，CNN 社区存档和同期报道不拼成一条曲线。
- `GET /api/health` 只投影两个默认行情的日期、取回时间和开闭市采样状态。健康检查与行情响应按同一日线完整性规则判断，实际采集年龄照实保留，不为了变健康而更新数据。五分钟仅为缓存/刷新周期，不是日线过期标准。
- 日线应到截止点是北京时间 16:00、美东时间 17:00（常规收盘后一小时的产品宽限，非上游承诺）。此前接受最近完整交易日；周末、已核验整日节假日跳过，最多回看 14 个日历日。当前 NY 提前收市仍沿用 17:00 保守截止点，没有假称包含提前收市时刻；盘中采样不能在闭市后冒充完整日线。时区遵循现有上海/纽约与 DST 规则，未知日历覆盖范围不确认健康。缓存失效只重新读库，不触发行情更新。
- 精确代码搜索先按 `market_snapshot` 主键投影已有 instrument 元数据（每条最多 1KB，CN 六位代码最多两个交易所候选）。命中直接返回已准备标的，无上游调用、无历史初始化；名称模糊查询和未准备代码才走现有有界建议源及失败退避。没有新增 Yahoo 行情回退或表字段。
- 搜索仍允许按需搜索源请求；最多 60 字符输入、100 项源结果、10 项返回，同键合并、5 分钟缓存、失败退避。它不是行情历史初始化入口。

## 最小持久存储

沿用现有 D1 绑定 `SENTIMENT_DB`，只新增一张实际使用的表（迁移 `0003_market_snapshot.sql`）：

| 字段 | 必需用途 |
| --- | --- |
| `key` | `market/symbol` 主键，定位、去重和按标的隔离 |
| `payload` | `calculation` 保存真实日线、逐日计算值和 RSI/EMA 递推检查点；`view` 保存一年展示结果，供情绪修订时组成响应；`http.body` 保存实际 HTTP 响应文本，避免每次请求完整解析和编码 |
| `updated_at` | 一次成功原子替换的时间，CAS 条件防止旧作业覆盖新作业，并用于响应 ETag；不是市场收盘时间 |

没有行情审计、批次、版本、队列、来源字典或无用预留字段。行情原发布者/渠道保留在 `view.source`，本站技术计算使用明确 `technicalSource=trendbeak_technical_v1`，不会冒充 CNN 或百分位情绪算法。情绪原始历史仍只保存在 `sentiment_daily`；HTTP 响应中只物化当前实际展示窗口的来源观测。

生产已完成真实三行初始化：CN 640 根（2024-03-11 起）、US/NVDA 各 501 根（2024-10-31 起），均截止 2026-10-30；含预生成响应和实际指标字段的 payload 为 CN 1,076,368、US 997,945、NVDA 1,006,567 字节，合计3,080,880字节，每行限制1.8 MB。展示视图 CN 242、US 251 个交易日，实际 API 含情绪约 196–216 KB/标的。只占既有 D1 存储/读写额度；没有新增付费资源或凭证，也未声称账户一定有剩余免费额度。表内 JSON 上限 1.8 MB，低于 D1 单行/值 2 MB 限制；使用参数绑定，避免大 SQL 字面量超过 100 KB。[D1 限制](https://developers.cloudflare.com/d1/platform/limits/)

初始化最多 640 根，更新后检查点最多 800 根。保留有限的原起点，防止每日丢弃前缀后重置递归指标。达到 800 必须显式受控重建，不能在用户请求或普通同步中自动截断/重建。表并非永久逐时行情档案，不采集分钟线。

## 独立初始化、更新和修复

本地默认连接 `.wrangler/state`，以下命令不操作远端：

```sh
npm run market:schema
npm run market:init -- --market CN --symbol 000300.SS --file /private/reviewed/cn-normalized.json
npm run market:init -- --market US --symbol '^GSPC' --file /private/reviewed/us-normalized.json
npm run market:init -- --market US --symbol NVDA --file /private/reviewed/nvda-normalized.json
npm run market:sync -- --market CN --symbol 000300.SS --dry-run
npm run market:sync -- --market US --symbol '^GSPC'
npm run market:sync -- --market US --symbol NVDA
```

`--file` 可为已验证紧凑行情（含真实 `fetchedAt`），或原始源响应；原始文件必须附实际抓取时间 `--fetched-at <ISO-timestamp>`，不能以重放时间伪装刚抓取。无文件时独立命令只抓一次指定源，不重试、不切主机绕限流。输入文件最多 2 MB，源 HTTP 最多 512 KB、超时 8 秒。重复 `init` 先查主键，已存在直接退出：0 上游、0 计算、0 写入，连输入文件也不打开。`--dry-run` 输出窗口、请求/读写/计算行数但不写库。

日常受控更新建议在对应市场收盘后各运行一次（CN 北京时间、US 美东时间，考虑夏令时），不是每五分钟跑历史任务。目前没有创建计划或自动化，发布也不会自动启动同步。

- 腾讯参数已实际验证 `sh000300,day,,,10,qfq` 返回 10 根（2026-10-19 至 2026-10-30）；普通同步取 10 根，延误时按距上次日期取必要重叠、最多 32 根。首次初始化/明确重建才取 640。
- Yahoo 普通同步用 `range=5d&interval=1d`，超过两日、最多二十八日的中断预先用 `range=1mo`，确保5日窗口不会只剩前次末日、丢失两个已完成价格校验锚点。既有第一方响应 `meta.validRanges` 明确列出 `5d`、`1mo`、`2y`（2026-09-30 已保存核验响应）；本次实时小窗口请求收到 429，未重试或换域绕过。因此不能宣称本轮已成功实时核验 Yahoo 增量。没有使用未经证实的 `since` 或 `period1/period2` 差量参数。Yahoo 返回的是重叠小窗口，不是严格逐条变更日志。
- 两源合并真实新日和明确近期修订；相同输入零指标重算，新日一行；此前盘中末行要先结算，多算一行。RSI/EMA 递归影响从最早修订日延续到末行；过去值无未来数据。52 周、20 日和此前最多 252 个有效分位观测仍遵守原算法。
- 至少两个完整未变价格重叠作为一致性检查；多日价格变化、源报告拆股、重叠日期删除、旧输入、超过 32 根增量、超过 28 日中断或达到 800 根均停止，保留原行，不自动全量请求。单个近期修订/补缺由正确后缀重算处理。
- 小窗口不能发现窗口外历史修订，也不能仅凭两个锚点证明所有旧数据未复权。明确复权/较早修订/长缺口时，单独审阅并运行下方受控重建；可低频安排人工检查，但没有自动任务或隐藏全量兜底。US 沿用 Yahoo `quote.close`，不混入 `adjclose`。

```sh
npm run market:rebuild -- --market US --symbol NVDA --dry-run
# 审阅后，同一显式操作去掉 --dry-run；失败保留旧快照
```

每次写入一次原子替换，`UPDATE ... WHERE updated_at=原值`；并发冲突报错不盲重试。不同实例即使误同时执行也不会覆盖较新行，但可能各自发一次上游请求；没有宣称全局分布式锁。首次新标的同键 INSERT 冲突不覆盖。

远端命令必须额外 `--remote`、明确设置现有 `CLOUDFLARE_ACCOUNT_ID`，仅使用现有环境 token 或未过期 Wrangler OAuth。缺失/过期就停止，不创建凭证、不自动登录、不改权限、不接受协议。本次已按用户“迁移部署并验收”授权，在既有库执行增量迁移、参数化初始化与响应准备。情绪 8,287 条及完整校验摘要保持一致。迁移不等于自动同步，也不代表新 Worker 已通过生产验收；每次发布须核对实际 SHA、绑定和两个域名。

## 可驱逐缓存与失败

行情内存最多 32 键，5 分钟，不使用行情边缘副本。完整视图在写入器校验；入口只检查必要身份、来源、日期和字节边界，内存保存不可变 JSON 字节。冷、到期、驱逐、独立实例都只按主键读 D1 的预生成响应，零行情上游、零指标计算、零写库。

同实例同键 singleflight，最多八个进行中键。D1 失败每键退避 60 秒；已有内存视图保留实际取回时间供陈旧展示，空实例返回明确 503。没有跨实例全局去重；失效并发最多造成受限 DB 读，不会引起上游/计算风暴。

情绪快照新鲜期 5 分钟，最后成功缓存最多 7 天；失败保留同源历史。投影只在快照变化时生成，热读不重新遍历情绪。浏览器最多 6 份/2 MiB/7 天备份，旧来源不会覆盖当前 D1 情绪。页面可见时至多每五分钟检查，visibilitychange 不绕过间隔；旧 4c00 页面仍可能一分钟轮询，但只收到物化结果/304，不触发历史工作。

## 预生成 HTTP 响应

`payload.http.body` 由独立命令生成，保存当前实际兼容消费者需要的完整数据 JSON（不包含随读取变化的新鲜度）。`view` 用于情绪修订时重新组成响应，避免重新计算指标；`http.body` 用于 HTTP 原样读取。读请求只追加小型新鲜度元数据，不解析或序列化整个 body，也不读情绪表。没有预留版本字段：已有 `updated_at` 就是 CAS 与 ETag 的版本。冷 304 的 SQL 先比较 `updated_at`，CASE 短路后不执行正文提取，也不接收 body。

```sh
npm run market:prepare -- --market CN
npm run market:prepare -- --market US
# 单标的与只读审阅
npm run market:prepare -- --market US --symbol NVDA --dry-run
```

准备命令最多处理一个市场32个明确已存在标的，超过则要求显式指定。重复且内容未变不写入。行情 init/sync/rebuild 会先组好响应再一次 CAS 替换；情绪 seed/sync 成功后刷新该市场的响应，失败会明确报告“情绪已导入，响应准备失败”，可独立重跑 prepare，读路径不代劳。刷新保留价格取回时间、计算检查点和所有来源，不触发上游或技术指标计算。远端仍需显式 `--remote` 与现有账户ID。

视觉中未准备的茅台交互使用已核验股票身份的受控搜索输入；NVDA使用实际搜索与已准备行情，分别验证第三方搜索可用性与本地状态交互，避免外部搜索超时阻断所有布局检查。

单值条件请求改为一次带 CASE 短路的按键 SQL：先比较 `updated_at`，匹配时不执行任何正文 JSON 提取；不匹配时同一次读取返回正文。测试覆写 SQLite `json_extract` 为抛错函数，证明 304 分支调用次数为零。当前只有少量明确路由，使用 Hono LinearRouter，避免首次请求构造通用正则路由匹配器；匹配循环数量由固定路由表限定。

## 单入口构建

后续生产35次检查曾捕获两次12 ms；传输实验的一次304也达到14 ms，所以不能将先前低样本称为预算全面通过。分段压缩在Chrome中未通过解码验证，未发布且已清理试验字段；最终仍使用普通预生成JSON。只查询一个时间字段的无框架对照4次为0–1 ms。检查产物确认原构建插件额外生成第二层 Hono/SmartRouter；现在直接构建唯一 Worker，沿用仓库已有 `_routes.json`，没有修改源站路由或权限。行情读取另外直接使用原生Response，省去通用Context和逐项响应头包装；情绪、搜索等路由仍沿用既有Hono。完整候选仍须以实际 Worker 日志验收，不能用对照或 Node 数字替代。

## 指标状态与读取交互

RSI14保留0–100原值，状态对比前一有效日；EMA保留有正负的20/60偏离，分离强度独立取绝对偏离在此前最多252个有效观测的历史分位（至少60个）。旧的有符号EMA分位保留供已打开的旧客户端使用，新增 `ema.strength` 才供当前图形使用。RVOL20保留倍数和历史活跃度，不把放量解释为看多。布林使用不截断的%B位置、带宽历史分位、带宽变化和中轨变化；%B≤20/≥80的“靠近轨道”是本页明确位置规则，越轨保留小于0或大于100的实值，零带宽不造50。方向、状态、强度与原始值分开；雷达面积不合成总分、买卖概率。
