# US sector ETF valuations

The US panel maps the eleven equity sectors to XLK, XLF, XLV, XLY, XLP, XLC, XLI, XLE, XLB, XLU and XLRE. It shows PB and PS estimates in multiples. Daily-close estimates use the selected date exactly. Portfolio-mark estimates retain their actual quarter-end date and can appear only on or after their real publication time. Missing observations stay blank. This release does not manufacture historical values or percentiles, and never applies today's holdings to an earlier date.

## Calculation and admission

`scripts/us-etf-valuations.mjs` is a pure, bounded calculation over explicitly reviewed, dated local inputs. No new market-data provider is contacted by a reader or by the importer. Public accessibility of a source is not a redistribution license: production inputs need source-use review separately from numerical validation. Synthetic fixtures are test-only and must not be imported into production.

For each security, market cap is the unadjusted closing price multiplied by actual outstanding common shares. A separate `portfolio_fair_value_per_share` mode uses the fund's reported quarter-end valuation mark, not an exchange closing price. That mode requires both the real quarter-end date and actual filing availability timestamp; financial statements must still have been publicly available by the quarter-end financial cutoff. EPS weighted-average shares are rejected. The specifically reviewed Visa/XLF case may instead use `event_reconstructed_common_equivalent` components with cited public class-conversion events. This is explicitly estimated common-equivalent capital, never labeled an actual quarter-end register. The observation retains an event-reconstruction flag and XLF is labeled once when this estimate contributes. Other estimated-share bases remain rejected. The shares and price must identify the same split/share basis. The latest verified actual share observation may be carried forward for at most 180 days; an age over 90 days is recorded separately. A known unresolved split is rejected. Incomplete corporate-action review is an explicit warning, never an invented adjustment.

PB uses common equity. Consolidated equity needs explicit NCI and preferred equity deductions; parent equity already excludes NCI and needs only preferred equity. Common equity permits neither deduction again. PS uses trailing twelve-month revenue. The specifically reviewed Comcast/Versant separation in XLC may use `ttm_pro_forma_comparable`: published pro-forma prior-year revenue minus comparable prior-year Q1 plus reported current Q1. It remains flagged on every observation and is labeled once in the table as adjusted comparable revenue, not pure reported GAAP TTM. The separately reviewed XLI/HONA spin-off uses sourced `common_pro_forma_event_bridge` equity and `ttm_carve_out_reported` revenue; these are flagged as event pro-forma estimates, not actual quarter-end balance-sheet figures, with one compact XLI label. Other unrecognized revenue bases are rejected. Facts after the valuation day's 16:00 New York cutoff are rejected. Facts may have different period ends; available-at timestamps, not aligned quarter labels, determine eligibility.

The aggregate is the weighted harmonic mean, `sum(valid original fund weights) / sum(weight / individual multiple)`. Nonpositive common equity is excluded only from PB; positive TTM revenue may still contribute to PS. Missing data is never zero. Missing, unknown or misspelled share-class status is missing capitalization. Only `verified_all_common` or the explicit `single_common_class_assumed_from_standard_issuer_fact` estimate status is admitted without class components; the latter always retains an incomplete-review warning, and cannot substitute for a known class issue. Known class-only capitalization cannot be divided by whole-company fundamentals; it remains missing unless complete class components are supplied. A reviewed multi-class input sums each class price × actual class shares. A price proxy requires a cited economic-unit conversion; an actual price for the same class requires factor 1. Repeated fund tickers of one issuer must share one identical company capitalization and financial basis, so their weighted reciprocal terms are the merged issuer weight rather than duplicate company values. At least 98% of the fund's equity holding weight must have verified applicable inputs or a known nonpositive denominator before the metric is admitted. Positive eligible weight and count, missing weight, excluded weight, and verified coverage remain separate metadata. These are covered-holding estimates, not an issuer-published complete-fund ratio.

An optional same-date `sourceComparison` records a separately calculated issuer-disclosure alternative with its own source, verified coverage and actual review timestamp. It never changes the primary regulatory-filing result or blends holdings. An alternative below 98% coverage stays blank. Relative differences are computed from the two qualified values, not treated as uncertainty bounds. The table's compact conflict control reveals both values and a readable current review date. This is explicitly a current audit annotation on a historical observation, not a comparison claimed to have been available at the historical close.

## Bounded storage and reads

Each ETF uses one existing three-field `market_snapshot` row, keyed `valuation/US/CODE`. Its payload contains up to 366 real dated prepared readings and the latest consumed input, per-observation source references, share-age and quality information. Source evidence remains internal under the real observation date, so a later quarter never erases the previous quarter's citations. Fixed quality-flag counts also remain on each historical reading, so later imports cannot erase a past observation's warnings. No new table, audit log or speculative schedule is created. Historical points contain `asOf`, `methodVersion` and quality coverage; percentiles are always null until a separately reviewed, genuine comparable historical series is available.

`GET /api/valuations/US?date=YYYY-MM-DD` performs one fixed eleven-key SQL projection, iterating at most 366 actual stored observations per key and returning at most 4 KB per prepared observation. It does not return the source documents or constituent input, fetch any provider, recalculate a valuation or initialize anything. Frontend date changes abort previous reads and ignore late replies. Daily readings never fall back to another date. For quarterly marks, the endpoint selects the most recent genuine snapshot whose availability is no later than the selected close. A filing disclosed after 16:00 New York is not visible at that day's close. The UI labels the quarter-end date once; it does not relabel that valuation with the selected day.

## Controlled import

The input schema is illustrated by `tests/us-etf-fixture.mjs` (synthetic tests only). The pure calculator also has an explicitly opt-in `researchOnly` mode for `reported_snapshot_price` inputs. The production importer and public schema reject this basis. It supports internal arithmetic cross-checks without inventing historical availability or source rights.

Original equity weight can be provided as `stockWeight`; the conservative default is 1. Source references are stored internally, not rendered as page prose. Reviewed dates should match the page's selected session; an older estimate is not relabeled as current.

```
node scripts/us-etf-valuation-import.mjs --file REVIEWED_INPUT.json
node scripts/us-etf-valuation-import.mjs --file REVIEWED_INPUT.json --remote --write --backup ABSOLUTE_PRIVATE_BACKUP
```

Dry-run is the default. The shared writer lock serializes local writers. Every candidate is validated before a single compare-and-swap SQL statement atomically publishes the requested batch. Actual writes require an exclusive private backup. Identical reruns write nothing. A changed existing observation or an attempt to roll the latest date backwards fails for explicit review. An uncertain remote outcome must be inspected before retrying. This importer is not connected to daily synchronization until a verified acquisition route is available.
