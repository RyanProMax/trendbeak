# 每日增量与读取缓存

## 实现与启用状态

现有三个预备标的：CN/000300.SS、US/^GSPC、US/NVDA。`npm run daily:sync -- --market CN|US --remote [--dry-run]` 只更新这些已有快照，不初始化未知标的。没有接入新的六轴、Futu估值或自算情绪。

工作流 `.github/workflows/daily-sync.yml` 已准备，当前尚未发布或启用。检查时仓库没有既有 Actions Secret/Variable；没有创建凭据，也没有复制本机交互式登录令牌。启用仍需要获准用于该现有D1的执行凭据、`CLOUDFLARE_ACCOUNT_ID`配置，以及明确设置 `DAILY_SYNC_ENABLED=true`。未配置时定时job跳过，不能称日更已自动运行。手工dispatch仅允许main，并在缺少凭据时明确失败。

Cloudflare执行令牌仅注入凭据检查与实际同步两个步骤；checkout、Node设置及依赖安装步骤不继承该令牌。没有把令牌写入跨步骤环境或输出。

现有Pages不提供Cron，需要独立执行环境；使用已有GitHub Actions的Node执行受控计算，保持HTTP Worker轻量，未增加Worker/队列/表或付费资源。

## 日程与互斥

- A股：周一至周五08:37 UTC，即上海16:37。
- 美股：周一至周五23:37 UTC，即纽约冬令时18:37、夏令时19:37；都在正常及提前收市之后，也晚于当前CNN镜像声明的23:00 UTC更新。来源晚到则失败保留旧值，不重试抓全量。
- 运行时再按市场本地日期、现有交易日历及结算时间门限判断。周末、已知整日节假日或盘前不请求来源、不访问D1。日历未覆盖则停止；GitHub定时可能延迟，不承诺准确秒级执行。
- 两市场及手工dispatch共用一个Actions `concurrency`组，写入中的任务不会被取消。每job最多8分钟，无自动重试。本机CLI另有排他目录锁，异常残留须先检查实际运行/写入状态，不能盲删重跑。模块的WeakSet只保护同一连接/进程；不能称分布式锁。每个快照仍用旧版本CAS防止覆盖并发变化。
- 生产手工修复应先暂停定时并确认在途任务结束；不要从另一执行环境绕过该writer队列并发写。此方案不声称两张表或两个标的一次全局事务。

## 来源、数据量与发布

行情沿用腾讯和Yahoo的既有渠道，正常腾讯请求10根、Yahoo请求5日；积压时仍受最多32根/28日边界约束。真实小窗验证：000300返回10根，SPX返回5根，均无全量回退。最多800根检查点超限、缺交易日、复权/拆股、价格基准不一致或超量均停止并保留旧视图；显式修复另行执行。

情绪仅更新`baifenwei`和`cnn_whit3rabbit`最近15个日历日期内的真实交易日；`cnn_benzinga`独立补录保留且不自动修订。中国使用现有完整CSV的HTTP尾部范围；美国使用同一whit3rabbit渠道的`datasets/cnn_fear_greed.csv`，没有使用其混合来源总表。先读取128字节核对表头，再取尾部4096字节，两次强ETag必须一致，`Content-Range`、实际字节数与窗口覆盖均检查。任一服务忽略Range时立即取消，绝不接受完整下载作为回退。相同日期相同分数去重，不同值冲突则拒绝；完整窗口缺数则不伪造或回填。

先获取并验证所有必要输入、计算最小受影响后缀、生成可用响应，再开始写入。情绪分数未变时不写行；行情无变化时保留原视图、真实日期和采集时间。即使指标无变化，也在受控job中核对有界响应投影，因此一次“情绪已入库但响应写入失败”能在下次运行修复。快照逐行CAS发布；源/计算/准备失败时旧快照不变。若实际写库阶段出现异常，停止并从日志和当前D1状态确认已完成部分；已保存的真实情绪不会删除，旧响应继续可读。

真实短窗与原存档可能存在修订，只允许指定渠道在该窗口内更新，不无标记混源。HTTP请求不会调用任何上述任务。

## 缓存

行情读取顺序为所在Cloudflare位置的Cache API、实例内存、有界D1预生成正文。命中边缘响应不查D1版本，不解析/重新计算历史；命中ETag返回空304。错误、404和304不缓存成正文。内存与边缘使用相同5分钟时间桶，因此源成功发布后，下一桶的读取可取得新版本，不会叠加两轮TTL。已打开页面仍遵守原有刷新间隔。

Cache API不是全球共享内存，可能被驱逐；同一实例已有singleflight及并发上限，不能声称跨实例锁。缓存失效仅回D1，绝不回源、写库或重算指标。D1故障时已有实例保留原有效快照及采集日期；没有可用记录的冷实例明确失败。健康检查保持独立的必要元数据读取。

## 验证与运维边界

本地测试覆盖重复调度零写入、单日追加、修订后缀、分来源修订、源错误/缺数/未收盘/拆股/超量、并发防覆盖、发布失败修复、跨模拟实例边缘命中零D1/零上游、冷miss仅D1、桶过期后新版本，以及Range不生效/ETag变化/截断/重复日期。原完整回归和本地CPU预算也需通过。

本机Node的CPU不能代替真实Worker日志。新版本未发布前，不宣称Cloudflare冷启动预算、实际跨地域缓存传播或真实定时执行已验收。启用后应记录首次两市场运行的来源请求数、读写行数、计算行数和成功版本，核对两域名读到该版本；没有自动重试风暴或付费扩容。
