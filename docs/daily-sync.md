# 每日增量与读取缓存

## 实现与启用状态

现有三个预备标的：CN/000300.SS、US/^GSPC、US/NVDA。`npm run daily:sync -- --market CN|US --remote [--dry-run]` 只更新已有行情和按来源隔离的恐贪，不初始化未知标的。随后 `node scripts/overview-job.mjs --market CN|US --remote` 更新已上线的 CN 辅助因子、12 项指数 PB/PS 或 US CNN 分项；CN RSI 随行情增量生成。估值使用易方达现有检查点，不依赖 Mac OpenD。

工作流 `.github/workflows/daily-sync.yml` 已发布并于 2026 年 11 月 5 日启用。此前最近五次定时运行均因没有启用变量而跳过；仓库也未配置执行凭据。本次经用户明确批准，创建了仅限 trendbeak 账户 D1 Write 的专用 Token，并加密保存为 Actions Secret `CLOUDFLARE_API_TOKEN`；配置账户变量与 `DAILY_SYNC_ENABLED=true`。没有升级 Cloudflare 套餐，也没有复制本机交互式登录令牌。令牌仅用于现有数据库同步。

若以后缺少启用配置，定时运行会在第一步明确失败；凭据、账户或启用开关不齐全时不会写入。手工 dispatch 仅允许 main，并会在受控同步前验证 D1 凭据和三个既有快照是否可读。补偿检查读取必要的既有完成元数据，不把节假日当作无需检查积压的理由。

Cloudflare执行令牌仅注入凭据检查、行情同步、六轴/估值同步三个步骤；checkout、Node设置、依赖安装及冻结时钟步骤不继承该令牌。没有把令牌写入跨步骤环境或输出。

现有Pages不提供Cron，需要独立执行环境；使用已有GitHub Actions的Node执行受控计算，保持HTTP Worker轻量，未增加Worker/队列/表或付费资源。

## 日程与互斥

- A股：周一至周五08:37 UTC，即上海16:37。
- 美股：周二至周六03:37 UTC，即纽约前一交易日冬令时22:37、夏令时23:37；在正常及提前收市之后。来源晚到则失败保留旧值，不重试抓全量。
- CN 补偿：每天12:17、20:17 UTC，即上海20:17、次日04:17，包含周末和节假日。每次分别检查核心行情/恐贪、辅助因子/估值是否已覆盖目标日；完整时各自只读少量元数据，零上游、零计算、零写入。不新增检查表或时间戳，不把低频补偿称为绝对准时保证。
- 完成判断同时使用现有 `updated_at`：源检查点或近15日情绪比已发布视图更新时，不跳过修复。仅校验器更新也可能保守地触发一次有界条件检查，未变观测不重算、不改真实采集日期；不为消除这类保守检查新增版本字段。
- 每次 job 冻结一个 UTC 时刻，两个同步步骤使用同一 `--at`。按各自市场时区、已核交易日历及结算门限（上海16:30、纽约17:30）向前查找最多14个日历日，选择最近已结算交易日。跨到次日、周末、节假日仍能补前日；日历未覆盖就失败。主日更仍检查有界修订，只有 `--catch-up` 补偿模式在完成后跳过来源。不得将“执行当天盘前”记录为绿色的无目标跳过。
- 腾讯/Yahoo 仍只取既有小窗。若响应包含次日盘中 bar，只保留已确认结算目标及之前的真实 bars，不将当日盘中 bar 改成收盘；目标日未到或缺失仍失败。取得的更晚情绪行只在实际当地日期内验证并排除，不冒充目标日。更晚的已有快照不倒退。
- GitHub 明确说明 schedule 可能延迟，负载高时甚至丢弃事件，因此仅凭提交或 cron 配置不能确认当天运行成功。两次补偿仍依赖 GitHub best-effort；全部漏触发时可按下面流程手工恢复，无 HTTP 请求触发采集。[官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)
- 两市场及手工dispatch共用一个Actions `concurrency`组，写入中的任务不会被取消。每job最多8分钟，无自动重试。本机CLI另有排他目录锁，异常残留须先检查实际运行/写入状态，不能盲删重跑。模块的WeakSet只保护同一连接/进程；不能称分布式锁。每个快照仍用旧版本CAS防止覆盖并发变化。
- 恢复先检查该 workflow 的 queued/in_progress 与最新目标，优先使用既有 main 的 `workflow_dispatch`（指定 CN 或 US）；它与自然运行共享 writer 队列，无需关停/重开工作流，也不创建新凭据。执行结束核对准确 SHA、目标日、各模块源调用/计算/写入数及 health；再次执行应零写入。不要从另一执行环境绕过队列直接并发写。此方案不声称两张表或两个标的一次全局事务。

## 来源、数据量与发布

行情沿用腾讯和Yahoo的既有渠道，正常腾讯请求10根、Yahoo请求5日；Yahoo 距离快照日期超过2个自然日时预先选择已验证的1个月窗口，以保留前次末日之前至少两个价格校验锚点。旧阈值7日会在10月30日至11月5日的中断后只取得一个重叠日期，因而被校验拦截。积压时仍受最多32根/28日边界约束，不自动回退全历史。真实小窗验证：000300返回10根，SPX返回5根，均无全量回退。最多800根检查点超限、缺交易日、复权/拆股、价格基准不一致或超量均停止并保留旧视图；显式修复另行执行。

情绪仅更新`baifenwei`和`cnn_whit3rabbit`最近15个日历日期内的真实交易日；`cnn_benzinga`独立补录保留且不自动修订。中国使用现有完整CSV的HTTP尾部范围；美国使用同一whit3rabbit渠道的`datasets/cnn_fear_greed.csv`，没有使用其混合来源总表。先读取128字节核对表头，再取尾部4096字节，两次强ETag必须一致，`Content-Range`、实际字节数与窗口覆盖均检查。任一服务忽略Range时立即取消，绝不接受完整下载作为回退。相同日期相同分数去重，不同值冲突则拒绝；完整窗口缺数则不伪造或回填。

先获取并验证所有必要输入、计算最小受影响后缀、生成可用响应，再开始写入。情绪分数未变时不写行；行情无变化时保留原视图、真实日期和采集时间。即使指标无变化，也在受控job中核对有界响应投影，因此一次“情绪已入库但响应写入失败”能在下次运行修复。快照逐行CAS发布；源/计算/准备失败时旧快照不变。若实际写库阶段出现异常，停止并从日志和当前D1状态确认已完成部分；已保存的真实情绪不会删除，旧响应继续可读。

真实短窗与原存档可能存在修订，只允许指定渠道在该窗口内更新，不无标记混源。HTTP请求不会调用任何上述任务。

CN 的指数金额/换手、开盘红计数、易方达估值分别准备：一个来源网络失败不能阻止其他独立来源的有效更新。失败部分保留自己的检查点和原日期，不将旧指数金额拼到新活动日期。所有候选仍在写入前完成校验、按行 CAS 发布；最终日志列出各源日期、失败阶段和实际写入数，CLI 在部分失败时仍返回非零状态。遇到同一估值提供方的 403/429 或网络故障后停止该提供方，不探测其他指数路径绕过限制。没有全量回退，也没有把健康检查的行情日期等同于全部六轴/估值已完成。

## 缓存

行情读取顺序为所在Cloudflare位置的Cache API、实例内存、有界D1预生成正文。命中边缘响应不查D1版本，不解析/重新计算历史；命中ETag返回空304。错误、404和304不缓存成正文。内存与边缘使用相同5分钟时间桶，因此源成功发布后，下一桶的读取可取得新版本，不会叠加两轮TTL。已打开页面仍遵守原有刷新间隔。

Cache API不是全球共享内存，可能被驱逐；同一实例已有singleflight及并发上限，不能声称跨实例锁。缓存失效仅回D1，绝不回源、写库或重算指标。D1故障时已有实例保留原有效快照及采集日期；没有可用记录的冷实例明确失败。健康检查保持独立的必要元数据读取。
