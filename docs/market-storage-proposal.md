# 行情存储最小方案（待确认，未实施）

当前仍由页面请求触发上游读取，实例内短时缓存；没有行情落库、分钟采集或 Cron。旧报告表与新用途无关，不迁移、不复制旧 schema。

如果只解决美股情绪历史不断丢失的问题，最小新增一张 `sentiment_daily`：`market`、`trade_date`、`source`、`value`、`observed_at`、`is_final`，主键 `(market, trade_date, source)`。只写来源明确带日期的真实观测；现有来源的无日期比较值不回填。应区分盘中读数与已确认日终值，未确认时不伪装成收盘数据。开始保存只能积累今后的真实历史，不能补齐过去一年。

若另需独立于上游留存完整日线，再增加 `daily_bars`：`market`、`symbol`、`trade_date`、`open`、`high`、`low`、`close`、`volume`（可空）、`source`、`adjustment`、`observed_at`，主键 `(market, symbol, trade_date)`。只存确认收盘后的日线；盘中快照继续短时内存缓存，不存分钟或逐笔。复权口径与修订覆盖策略需先确认，避免把后续复权修订误称为当日存档。

RSI、MA20 偏离、量能比、52 周位置继续由截至该日的日线计算，不增设指标历史表；读取时用足够预热区间，缺失保持为空。首次历史导入只接受合法可达、可验证且口径一致的真实日线。

需要先决定：是否确需持久化；仅存两市情绪还是同时存两大盘日线；日终确认规则；采集频率与可接受缺口。按访问保存实现最小，但无人访问会漏日；稳定每日采集才需要调度。两者均未获批准，本轮不添加写库路径、自动任务、额外存储或新凭据。个股搜索仅作为按需查询，不默认永久积累所有搜索标的。
